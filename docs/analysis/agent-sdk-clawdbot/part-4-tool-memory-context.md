# Part 4. 도구, 기억, 맥락 관리

이 문서는 Clawdbot의 도구 호출 방식, 기억 구조, 맥락 정보 관리 흐름을 학습 관점에서 분석한다.

> 용어가 어렵다면 [README의 용어 해설](README.md#용어-해설)을 먼저 읽어보자.

## 한눈에 보기
- 도구는 실행 시점에 동적으로 조합되며, **채널 종류, 보안 격리 환경(샌드박스), 허용 규칙**에 따라 사용 가능한 도구가 달라진다.
- 기억은 **파일 기반**이다. `MEMORY.md`(장기 기억)와 `memory/YYYY-MM-DD.md`(일일 기록)가 핵심 저장소다.
- 맥락 정보(컨텍스트)는 시스템 지시문 + 워크스페이스 파일 + 대화 기록 + 도구 결과를 합쳐서 구성된다.

## 시각화: 도구 호출 흐름
```
[AI가 생성한 출력]
   |
   v
[도구 호출 요청] --> [허용 규칙/보안 격리 검사] --> [실행(로컬 또는 원격 기기)]
   |                                              |
   v                                              v
[도구 실행 결과] -----------------------------> [대화 기록에 저장]
   |
   v
[다음 응답 생성 또는 다음 도구 실행]
```

## 상세 분석
### 1) 도구 실행 방식
- 도구 목록은 실행 시점에 생성되며, `createClawdbotCodingTools(...)` 함수가 도구를 조합하는 핵심 지점이다.
- 채널별로 사용 가능한 기능이 시스템 지시문에도 명시되며, 도구 사용 가능 여부는 허용 규칙에 의해 제한된다.
- 도구 실행 결과는 실시간 이벤트(`tool` 채널)로 외부에 표시되고, 대화 기록에도 저장된다.

### 2) 실패 처리와 검증
- 도구 실행 전에 **허용 규칙과 보안 격리 환경 검사**를 먼저 통과해야 한다.
- 실패 시 오류 내용은 도구 결과로 저장되며, 필요하면 대체 응답(폴백 메시지)이 생성된다.

### 3) 기억 관리 방식
- **파일 기반 기억**: `MEMORY.md`는 장기 기억 파일, `memory/YYYY-MM-DD.md`는 날짜별 기록 역할을 한다.
- 대화가 너무 길어져 요약(컴팩션) 직전에 도달하면, **기억 저장 단계**(침묵 턴)가 실행되어 중요한 내용을 파일에 기록하도록 유도한다. 쉽게 말해, "지금까지 대화에서 중요한 것을 메모장에 적어두는" 과정이다.
- 기억 검색은 `memory_search`(기억 검색), `memory_get`(기억 가져오기) 도구로 수행되며, 기억 관련 플러그인(확장 기능)이 활성화되어야 사용할 수 있다.

### 4) 맥락 정보(컨텍스트) 관리
- AI가 한 번에 읽을 수 있는 정보량(컨텍스트 윈도우)은 AI 모델마다 한계가 있으므로, 안전 검사 로직으로 보호된다.
- AI 모델의 정보 처리 용량이 너무 작으면 실행이 차단되거나, 다른 모델로 자동 전환(페일오버)된다.

## 핵심 동작 흐름 설명
```
AI 엔진 실행 시도:
  도구 목록 = 도구 조합 함수(채널, 권한, 격리 환경...)
  시스템 지시문 = 지시문 생성 함수(에이전트 설정, 워크스페이스...)
  대화 내용 = 이전 대화 기록 + 초기 설정 파일 + 기억 조각들

  AI 모델 실행(시스템 지시문, 대화 내용)
    → 도구 호출 요청 발생
    → 허용 규칙/보안 격리 검사
    → 도구 실행
    → 결과를 대화 기록에 저장
```

## 학습자가 얻어야 할 포인트
- 도구 호출은 에이전트 동작의 핵심이며, **허용 규칙 + 보안 격리 환경 + 승인 체계**가 도구의 실질적 권한을 결정한다.
- 기억은 컴퓨터 메모리(RAM)가 아니라 **작업 공간의 파일**이라는 점이 중요하다. 파일에 적어두면 다음 대화에서도 기억이 유지된다.
- 맥락 정보는 시스템 지시문 + 워크스페이스 파일 + 대화 기록 + 도구 결과를 합친 것이다.
