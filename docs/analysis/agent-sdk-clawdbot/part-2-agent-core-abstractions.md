# Part 2. 에이전트의 핵심 개념

이 문서는 Clawdbot의 핵심 개념들을 학습 관점에서 정리한다. 각 파트는 독립적으로 읽을 수 있도록 구성되어 있다.

> 용어가 어렵다면 [README의 용어 해설](README.md#용어-해설)을 먼저 읽어보자.

## 한눈에 보기
- Clawdbot의 핵심 개념은 **에이전트, 세션, 워크스페이스, 도구/스킬, 모델/인증** 다섯 축으로 정리된다.
- "에이전트"는 단순히 AI 모델 하나가 아니라, **작업 공간 + 설정 폴더 + 대화 저장소**를 묶은 하나의 운영 단위다.
  - 여기서 "운영 단위"란, AI 모델을 **실제로 쓸 수 있는 상태로 만드는 데 필요한 모든 것을 묶은 패키지**를 말한다. AI 모델이 사람의 "두뇌"라면, 에이전트는 "책상(작업 공간) + 서류함(대화 기록) + 공책(기억) + 출입증(인증) + 도구함(스킬)까지 갖춘 직원 한 명"이다.
- 대화 기록(세션)은 **게이트웨이(중앙 서버)가 관리**하며, 모든 앱과 기기는 게이트웨이를 통해 대화를 확인한다.

## 시각화: 핵심 개념 구조
```
+-------------------------+          +---------------------------+
|       에이전트           |          |       게이트웨이           |
| (고유 ID, 설정 폴더,    |<---------|  대화 저장소와             |
|  작업 공간, 인증 정보)   |          |  메시지 전달 규칙을 관리    |
+-----------+-------------+          +-------------+-------------+
            |                                        |
            v                                        v
+-------------------------+          +---------------------------+
|     워크스페이스          |          |         세션(대화)         |
|  (설정 파일들: 성격,     |          |  대화 기록 파일 + 대화 ID  |
|   도구 목록, 기억 등)    |          |  대화키 → 대화 ID 매핑     |
+-----------+-------------+          +-------------+-------------+
            |                                        |
            v                                        v
+-------------------------+          +---------------------------+
|   스킬 / 도구            |--------->|    AI 엔진 (실행 환경)     |
|  도구 목록 + 허용 규칙   |          |  내장된 추론 엔진 실행     |
+-------------------------+          +---------------------------+
```

## 상세 분석
### 1) 에이전트 (하나의 AI 비서 단위)
- 에이전트는 고유한 ID(`agentId`)를 갖고, **작업 공간과 설정 폴더**를 보유한다.
- 설정 폴더에는 사용할 AI 모델 목록과 인증 정보(`auth-profiles.json`)가 저장되어, **에이전트마다 독립적인 설정과 권한**을 갖는다.
- 여러 에이전트를 동시에 운영하면, 하나의 게이트웨이 안에서 **서로 다른 성격/권한/AI 모델**을 가진 비서들을 운용할 수 있다.

### 2) 세션 (대화 상태 관리)
- 세션 키(대화 식별자)는 `agent:<에이전트ID>:...` 형태이며, 1:1 대화/그룹/스레드에 따라 규칙이 다르다.
- 세션 목록은 `~/.clawdbot/agents/<에이전트ID>/sessions/sessions.json`에 저장된다.
- 각 대화의 상세 기록은 `~/.clawdbot/agents/<에이전트ID>/sessions/<세션ID>.jsonl` 파일에 한 줄씩 기록된다.
- 핵심 원칙: **게이트웨이가 대화의 유일한 관리자**이며, 앱이나 기기는 게이트웨이를 거쳐 대화를 확인한다.

### 3) 워크스페이스 (파일 기반 작업 공간)
- 워크스페이스는 도구가 실행될 때의 기본 폴더이며, 에이전트의 성격과 능력을 정의하는 핵심 장소다.
- `AGENTS.md`(역할 정의), `SOUL.md`(성격), `TOOLS.md`(도구 설명), `USER.md`(사용자 정보), `IDENTITY.md`(정체성) 같은 파일이 **첫 대화 시작 시 AI에게 전달**된다.
- 에이전트의 "기억, 규칙, 말투"를 **파일로 선언**하도록 유도하는 설계다.

### 4) 도구 / 스킬 (에이전트가 하는 행동)
- 스킬은 **기본 제공 / 관리형 / 워크스페이스** 3단계에서 불러온다. 같은 이름의 스킬이 여러 곳에 있으면 워크스페이스 것이 우선된다.
- 실행 시점에 도구 목록이 구성되며, **채널 종류, 보안 격리 환경, 허용 규칙**에 따라 사용 가능한 도구가 달라진다.

### 5) 모델 / 인증 (AI 엔진 + 접속 권한)
- 어떤 AI 모델을 사용할지는 기본 설정 + 허용 목록 + 대화 중 변경(오버라이드)으로 결정된다.
- 인증 정보는 에이전트 단위로 관리되며, AI 제공사가 바뀌면 대화 중 변경 설정이 자동으로 해제된다.

## 핵심 동작 흐름 설명
```
에이전트 명령 처리(메시지, 대화키, 에이전트ID):
  설정 불러오기
  대화(세션) 찾기 또는 새로 만들기
  작업 공간(워크스페이스) 준비
  스킬 목록 구성

  AI 모델 결정 (기본 설정 + 허용 목록 + 대화 중 변경 확인)
  추론 수준과 상세도 결정

  내장 AI 엔진 실행 {
    대화키, 대화 기록 파일,
    작업 공간 폴더, AI 모델,
    인증 정보, 스킬 목록
  }
```

## 학습자가 얻어야 할 포인트
- 에이전트는 "AI 모델 하나"가 아니라, 작업 공간 + 설정 + 대화 기록을 포함한 **운영 단위**다.
- 대화(세션)는 게이트웨이가 관리하며, 앱이나 기기는 항상 게이트웨이를 통해 상태를 확인한다.
- 워크스페이스 파일은 **에이전트의 성격과 능력을 정의하는 핵심 설정**이며, AI에게 전달되는 지시문의 근간이다.
- 도구/스킬은 실행 시점에 동적으로 조합되며, **허용 규칙, 채널 종류, 보안 격리 환경**이 실질적 권한을 결정한다.
