# Part 1. 전체 구조와 설계 철학

이 문서는 Clawdbot 오픈소스의 에이전트(AI 비서) 시스템을 **학습 및 문서화 목적**으로 분석한 결과다. 각 파트는 독립적으로 읽을 수 있도록 구성되어 있다.

> 용어가 어렵다면 [README의 용어 해설](README.md#용어-해설)을 먼저 읽어보자.

## 한눈에 보기
- Clawdbot은 **게이트웨이(중앙 관리 서버) 중심의 로컬 퍼스트(내 컴퓨터 우선) 에이전트 플랫폼**이다. 게이트웨이가 모든 채널 연결과 대화 상태를 관리하고, 에이전트(AI 비서)는 그 위에서 동작한다.
- 설계 철학은 "관리는 게이트웨이가, 실제 대화는 에이전트가 담당"하는 구조다. 하나의 중앙 연결 통로를 통해 모든 기기와 앱이 동일한 상태를 공유한다.
- 에이전트 실행 환경은 p-mono라는 기존 엔진을 **내장형**으로 사용하되, 대화 관리와 도구 연결은 Clawdbot이 직접 담당한다.

## 시각화: 전체 구조
```
[메시징 채널들]
(WhatsApp, Telegram, Slack, Discord, ...)
            |
            v
+----------------------------+
|    게이트웨이 (중앙 서버)     |
|  모든 연결과 상태를 관리     |
+-------------+--------------+
              |
    +---------+---------+------------------+
    |                   |                  |
    v                   v                  v
[에이전트 실행 환경]  [관리 화면/명령어]   [기기 앱들]
(내장된 AI 엔진)    (웹/터미널 제어)    (macOS/iOS/Android)
    |
    v
[작업 공간 + 대화 기록 + 도구]
```

## 상세 분석
### 1) 시스템의 목적과 철학
- **로컬 퍼스트(내 컴퓨터 우선)**: 기본적으로 내 컴퓨터에서만 접근 가능하도록 설정되어 있고, 외부 접속은 보안 네트워크(Tailscale 등)를 통해서만 가능하다. 즉, "내가 소유한 서버"를 신뢰 기준으로 삼는 구조다.
- **하나의 중앙 관리**: 게이트웨이가 모든 채널(WhatsApp, Telegram 등)과 대화 기록, 이벤트를 통합 관리한다. 모든 앱과 기기는 게이트웨이에 연결해 상태를 확인하고 명령을 보낸다.
- **플랫폼 지향**: 단순한 프로그래밍 라이브러리(코드 조각)가 아니라, 게이트웨이 + 실행 환경 + 채널/기기 연결까지 포함하는 **통합 운영 시스템**을 목표로 한다.

### 2) 설계 의도
- "사용자가 느끼는 경험은 어떤 채널을 쓰느냐가 아니라, **에이전트와의 대화 흐름 그 자체**"라는 관점이 핵심이다. WhatsApp이든 Telegram이든 동일한 대화 흐름으로 수렴한다.
- 도구 실행은 게이트웨이나 연결된 기기에서 수행되며, AI 엔진은 이를 하나의 반복적인 작업 루프(요청 받기 → 생각하기 → 실행하기 → 응답하기)로 관리한다.

### 3) 장단점 교환 관계 (개요)
- 하나의 게이트웨이에 집중하면 **상태 일관성**(어디서든 같은 정보를 보는 것)과 **운영 단순성**을 얻지만, 게이트웨이가 멈추면 전체가 멈추는 **단일 장애점**이 될 수 있다.
- AI 엔진을 내장하면 설치와 문제 추적이 단순하지만, 규모를 키우기 어려운 한계가 있다.

## 핵심 동작 흐름 설명
```
// 메시지가 들어오거나 명령어가 실행되면
게이트웨이가 요청을 받는다
  → 에이전트 명령 처리 시작
     → 대화 기록(세션)과 작업 공간(워크스페이스) 준비
     → 사용 가능한 스킬(능력 목록) 구성
     → 내장 AI 엔진 실행
        → 시스템 지시문과 도구 목록 구성
        → AI 반복 루프 실행 (생각 → 행동 → 관찰)
     → 최종 응답 전달
```

## 학습자가 얻어야 할 포인트
- Clawdbot은 단순한 "AI 개발 도구"가 아니라 **게이트웨이 중심의 운영 플랫폼**이다.
- 대화 기록(세션)과 작업 공간(워크스페이스)이 AI 동작의 중심이며, 메시징 채널은 입력/출력 통로일 뿐이다.
- 기존 AI 엔진(p-mono)을 재사용하되, **대화 관리와 도구 연결은 Clawdbot이 독자적으로 설계**했다.
