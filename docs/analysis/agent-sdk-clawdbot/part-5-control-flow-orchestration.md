# Part 5. 실행 흐름과 작업 조율

이 문서는 Clawdbot의 실행 흐름, 대기줄/레인 구조, 여러 에이전트 간 메시지 전달을 학습 관점에서 분석한다.

> 용어가 어렵다면 [README의 용어 해설](README.md#용어-해설)을 먼저 읽어보자.

## 한눈에 보기
- 에이전트 실행은 **대화(세션) 단위로 순서대로 처리**하는 것이 기본이며, 레인(실행 대기줄)을 통해 제한적으로 동시 처리를 지원한다.
- 게이트웨이가 요청을 접수하고, 실제 실행은 `에이전트 명령 처리 → 내장 AI 엔진 실행` 경로로 흐른다.
- 여러 에이전트를 운영할 때는 **바인딩(연결 규칙)**으로 들어오는 메시지를 특정 에이전트에게 전달한다.

## 시각화: 실행 흐름과 대기줄
```
[들어오는 메시지]
       |
       v
  게이트웨이가 요청 접수
       |
       v
  에이전트 명령 처리
       |
       v
  내장 AI 엔진 실행
       |
       v
  대화별 대기줄 + 전체 대기줄에 등록
       |
       v
  AI 엔진 실행 (순서대로 처리)
```

## 상세 분석
### 1) 실행 흐름 구조
- 게이트웨이는 에이전트 관련 요청을 수신한 뒤, 어떤 대화인지 파악하고 실행을 시작한다.
- 실제 실행은 `에이전트 명령 처리` 단계에서 이루어지며, AI 모델/대화 기록/작업 공간/스킬 목록을 준비한다.
- `내장 AI 엔진 실행`은 대화별 대기줄과 전체 대기줄을 통해 실행 순서를 관리한다.

### 2) 대기줄과 레인(차선) 모델
- 레인(차선)은 `main`(기본), `cron`(예약 작업), `subagent`(하위 에이전트), `nested`(중첩 실행) 등으로 구분된다.
- **대화별 대기줄 + 전체 대기줄** 조합은 두 가지를 동시에 보장한다:
  - 같은 대화 안에서 요청이 겹치지 않도록 방지
  - 시스템 전체 자원이 과부하되지 않도록 보호
- 기본 동작은 하나씩 순서대로 처리하며, 필요 시 레인(차선)별로 동시에 처리할 수 있다.

### 3) 조건에 따른 분기와 동시 처리
- 대화별로 순서대로 처리하는 것이 기본이므로, 독립적인 동시 실행은 레인(차선) 분리를 통해 달성한다.
- 예: 예약 작업은 `cron` 레인을 사용해 일반 대화와 분리할 수 있다.

### 4) 여러 에이전트 간 메시지 전달
- 여러 에이전트를 운영하는 환경에서 메시지는 **바인딩(연결 규칙)**으로 전달된다.
- 각 에이전트는 자기만의 작업 공간과 대화 저장소를 갖고 독립적으로 실행된다.

## 시각화: 여러 에이전트 메시지 전달 구조
```
[채널에 들어온 메시지]
       |
       v
+------------------------+
| 바인딩 규칙 확인        |
| (어떤 에이전트로 보낼지) |
+---------+--------------+
          |
   +------+------+
   |             |
   v             v
[에이전트 A]   [에이전트 B]
(작업 공간 A)  (작업 공간 B)
```

## 핵심 동작 흐름 설명
```
게이트웨이가 에이전트 요청을 받으면:
  요청 내용 검증
  대화키/대화ID 확인
  요청을 접수하고 실행 ID 반환
  → 에이전트 명령 처리 (비동기 실행)

내장 AI 엔진 실행:
  대화별 대기줄에 등록
  전체 대기줄에 등록
  AI 엔진 실행 시도
```

## 학습자가 얻어야 할 포인트
- Clawdbot은 **대화 단위로 순서대로 처리**하는 것을 기본으로 하며, 레인(차선)으로 제한된 동시 처리를 제공한다.
- 게이트웨이는 실행을 시작하는 관문이며, 실제 준비와 실행은 에이전트 명령 처리 단계가 담당한다.
- 여러 에이전트 간 메시지 전달은 "바인딩(연결 규칙)"이라는 설정 방식으로 구현된다.
