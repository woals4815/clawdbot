# Part 6. 관찰, 안전, 확장성

이 문서는 Clawdbot의 시스템 관찰 기능, 안전 장치, 확장성 구조를 학습 관점에서 분석한다.

> 용어가 어렵다면 [README의 용어 해설](README.md#용어-해설)을 먼저 읽어보자.

## 한눈에 보기
- **시스템 관찰**: 에이전트가 어떻게 동작하는지를 실시간 이벤트 흐름(생명주기/비서 응답/도구 실행)과 대화 기록으로 파악할 수 있다.
- **안전 장치**: 보안 격리 환경(샌드박스), 도구 허용 규칙, 실행 승인 절차, 기기 인증(페어링)/1:1 메시지 정책이 다층으로 구성되어 있다.
- **확장성**: 스킬(능력 꾸러미)과 훅/플러그인(자동 실행 기능)을 통해 기능을 확장할 수 있다.

## 시각화: 훅과 이벤트 흐름
```
[에이전트 반복 루프]
   | (생명주기/도구/응답 이벤트 발생)
   v
[게이트웨이 이벤트 흐름] --> [관리 화면 / 로그 기록]
   |
   v
[플러그인 훅 (자동 실행 기능)]
(에이전트 시작 전 / 도구 실행 후 / 에이전트 종료 시 ...)
```

## 상세 분석
### 1) 시스템 관찰 (무슨 일이 일어나는지 보기)
- 에이전트 실행 중에는 `lifecycle`(생명주기), `assistant`(비서 응답), `tool`(도구 실행) 세 가지 종류의 이벤트가 발생한다.
- 대화 기록 파일(JSONL)은 실행 결과의 "증거 기록" 역할을 하며, 관리 화면은 이를 기반으로 상태를 표시한다.
- 시스템 지시문 보고서가 생성되어, AI에게 전달되는 맥락 정보의 구성 비율을 파악할 수 있다.

### 2) 안전 장치 (위험한 동작 방지)
- **보안 격리 환경(샌드박스)**: 특정 대화 또는 모든 대화를 격리된 가상 환경(Docker 컨테이너)에서 실행할 수 있다. 마치 실험실의 안전 구역처럼, 외부에 영향을 주지 않도록 격리한다.
- **도구 허용 규칙**: 특정 도구의 사용을 허용하거나 차단하는 1차 안전 장치다.
- **실행 승인 절차**: 격리 환경 바깥에서 실행하거나 시스템 명령을 실행하려면, 별도의 승인 절차를 거쳐야 한다.
- **기기 인증(페어링)/1:1 메시지 정책**: 승인되지 않은 1:1 메시지나 새로운 기기는 자동으로 차단되거나, 기기 인증 절차를 요구한다.

### 3) 확장성 (기능 추가하기)
- **스킬(능력 꾸러미)**: 기본 제공/관리형/워크스페이스 세 곳에서 불러오며, 도구처럼 실행된다.
- **훅/플러그인(자동 실행 기능)**: 에이전트의 생명주기(시작/종료), 도구 호출, 대화 요약 등 다양한 시점에 추가 기능을 등록해서 자동으로 실행할 수 있다. 마치 알람처럼, 조건이 맞으면 자동으로 작동한다.

## 핵심 동작 흐름 설명
```
내장 AI 엔진 실행:
  '시작' 이벤트 발생
  비서 응답 조각을 실시간 전송
  '도구 시작/결과' 이벤트 발생
  '종료' 또는 '오류' 이벤트 발생

훅(자동 실행 기능):
  에이전트 시작 전 → 지시문이나 맥락 정보 수정 가능
  도구 실행 전 → 요청 내용 검증 또는 변환 가능
  도구 실행 후 → 결과 확인 가능
  에이전트 종료 후 → 후처리 가능
```

## 학습자가 얻어야 할 포인트
- 시스템 관찰은 실시간 이벤트 흐름 + 대화 기록 파일의 이중 구조로 확보된다.
- 안전 장치는 하나가 아니라, **도구 허용 규칙 + 보안 격리 환경 + 실행 승인 절차**를 조합한 다층 구조다.
- 기능 확장은 "도구/스킬 기반"과 "훅(자동 실행) 기반" 두 축으로 설계되었다.
